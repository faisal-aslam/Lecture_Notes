\section{Introduction}

We are given the following context-free grammar (CFG):
\[
\begin{aligned}
E &\to T\,R \\
R &\to +\,T\,R \mid -\,T\,R \mid \epsilon \\
T &\to \text{num}
\end{aligned}
\]

The goal is to build a calculator that:
\begin{itemize}
  \item computes the final result of an expression with addition and subtraction,
  \item counts the total number of operations (additions and subtractions) performed,
  \item and prints both using simple C \texttt{printf} statements.
\end{itemize}

The grammar is right-recursive: the whole expression is a first term \(T\), followed by a chain of ``\(+\,T\)'' or ``\(-\,T\)'' groups. Because the operators are consumed left to right, we keep a \emph{running total} in an inherited attribute \(R.i\). When the chain ends (\(R\to\epsilon\)), the running total is the final answer, and that is the point where we print it.

\section{Derivation and Parse Tree}

For the input \texttt{3+7-5}, a leftmost derivation is:
\[
E \Rightarrow T\,R \Rightarrow \text{num}\,R
\Rightarrow \text{num} + T\,R
\Rightarrow \text{num} + \text{num}\,R
\Rightarrow \text{num} + \text{num} - T\,R
\Rightarrow \text{num} + \text{num} - \text{num}\,R
\Rightarrow \text{num} + \text{num} - \text{num}
\]
The last step uses \(R\to\epsilon\).

\section{Syntax-Directed Translation (SDT)}

\subsection{Attributes}

Each nonterminal carries the attributes needed to evaluate the expression:

\begin{itemize}
  \item \(T.\text{val}\): the value of a number (synthesized).
  \item \(R.i\): the running total so far (inherited). It is set once at the start (from \(T.\text{val}\)) and updated at each ``\(+\,T\)'' or ``\(-\,T\)'' group.
  \item \(R.c\): the number of operations performed so far (inherited). It is set to \(0\) at the start and incremented by each operator group.
\end{itemize}

No attribute needs to be carried back to the root: the final result and the operation count are both known inside \(R\), and they are printed there at the base case \(R\to\epsilon\).

\subsection{Semantic Rules with \texttt{printf}}

The SDT actions below use C \texttt{printf}. They are placed inside the production bodies as required: an action that computes an inherited attribute goes immediately before the symbol that uses it; an action that prints the final result goes at the point where the value is finalized.

\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Production} & \textbf{SDT actions (C)} \\
\midrule
\(E \to T\,R\)
& \texttt{R.i = T.val;} \newline \texttt{R.c = 0;} \\
\midrule
\(R \to +\,T\,R_1\)
& \texttt{R1.i = R.i + T.val;} \newline \texttt{R1.c = R.c + 1;} \\
\midrule
\(R \to -\,T\,R_1\)
& \texttt{R1.i = R.i - T.val;} \newline \texttt{R1.c = R.c + 1;} \\
\midrule
\(R \to \epsilon\)
& \texttt{printf("total=\%d and the number of operations=\%d\texttt{\char`\\n}", R.i, R.c);} \\
\midrule
\(T \to \text{num}\)
& \texttt{T.val = num.lexval;} \\
\bottomrule
\end{tabular}
\end{center}

\paragraph{How the actions are placed.}
\begin{itemize}
  \item The two assignments in \(E\to T\,R\) set the inherited attributes of \(R\) (the running total \(R.i\) and the operation count \(R.c\)). They must be computed before \(R\) is evaluated, so they sit at the start of the body, just before \(R\).
  \item In the recursive productions \(R\to +\,T\,R_1\) and \(R\to -\,T\,R_1\), the running total \(R_1.i\) and the count \(R_1.c\) are inherited by the right-hand \(R_1\), so they are computed just before \(R_1\) in the body.
  \item In \(R\to\epsilon\) there is nothing left to read: the running total \(R.i\) is the final value of the expression and \(R.c\) is the final operation count. Both are printed with a single \texttt{printf}. This is the only place where printing happens, so exactly one line is printed per expression.
  \item In \(T\to\text{num}\), the value of the token is copied into \(T.\text{val}\) (synthesized attribute of \(T\)).
\end{itemize}

\subsection{Example: \texttt{3+7-5}}

The actions produce the following sequence of values and finally one \texttt{printf}.

\begin{center}
\small
\begin{tabular}{l l l l}
\toprule
\textbf{Step} & \textbf{Production} & \textbf{Action} & \textbf{Value} \\
\midrule
1 & \(T_1\to\text{num}(3)\) & \texttt{T1.val = 3} & \(T_1.\text{val}=3\) \\
2 & \(E\to T\,R\) (left part) & \texttt{R.i = T1.val} & \(R.i=3\) \\
3 & \(E\to T\,R\) (right part) & \texttt{R.c = 0} & \(R.c=0\) \\
4 & \(T_2\to\text{num}(7)\) & \texttt{T2.val = 7} & \(T_2.\text{val}=7\) \\
5 & \(R\to +\,T\,R_1\) & \texttt{R1.i = R.i + T2.val} & \(R_1.i=10\) \\
6 & \(R\to +\,T\,R_1\) & \texttt{R1.c = R.c + 1} & \(R_1.c=1\) \\

The final output is:
\begin{verbatim}
total=5 and the number of operations=2
\end{verbatim}

\section{C Code for the SDT}

The C code below mirrors the actions exactly. \(R\) receives the running total \(i\) and the running count \(c\) as parameters (these are the inherited attributes), updates them at each operator, and at the end prints the result. The \texttt{printf} occurs only once, inside the \(\epsilon\)-case of \(R\).

\begin{lstlisting}
#include <stdio.h>
#include <ctype.h>

char *input;
int pos = 0;

int T(void);
int R(int i, int c);

int E(void) {
    int t = T();
    int i = t;          /* R.i = T.val */
    int c = 0;          /* R.c = 0     */
    return R(i, c);
}

int R(int i, int c) {
    if (input[pos] == '+') {
        pos++;
        int t = T();
        return R(i + t, c + 1);   /* R1.i = R.i + T.val;  R1.c = R.c + 1 */
    } else if (input[pos] == '-') {
        pos++;
        int t = T();
        return R(i - t, c + 1);   /* R1.i = R.i - T.val;  R1.c = R.c + 1 */
    } else {
        printf("total=%d and the number of operations=%d\n", i, c);
        return 0;
    }
}

int T(void) {
    int v = 0;
    while (isdigit((unsigned char)input[pos])) {
        v = v * 10 + (input[pos] - '0');
        pos++;
    }
    return v;
}

int main(void) {
    char expr[100];
    printf("Enter expression: ");
    if (scanf("%99s", expr) != 1) return 1;
    input = expr;
    pos = 0;
    E();
    return 0;
}
\end{lstlisting}

\section{Conclusion}

The calculator uses the right-recursive grammar \(E\to T\,R\), \(R\to +\,T\,R\mid -\,T\,R\mid\epsilon\), \(T\to\text{num}\). The running total \(R.i\) and the running operation count \(R.c\) are inherited attributes; they are started in \(E\to T\,R\) and updated at each operator. When the input is exhausted, \(R\to\epsilon\) prints the final result and the number of operations with a single \texttt{printf}. No value is carried back to the root; the final state of the inherited attributes at the \(\epsilon\)-production is the answer.
